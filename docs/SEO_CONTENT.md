# SEO, Content and AI Search Readiness

## 1. Goal

Make useful, verified public information discoverable through
conventional search engines and eligible AI search experiences. No
implementation can guarantee indexing, rankings, citations or
recommendations by an AI system.

## 2. Technical SEO

-   Render public content server-side with stable, descriptive URLs.
-   Use unique title tags, meta descriptions, one clear page title and
    logical heading hierarchy.
-   Add canonical URLs where duplicate or parameterized pages exist.
-   Generate an accurate XML sitemap containing only canonical,
    indexable public URLs.
-   Configure robots directives carefully; do not block assets needed
    for rendering.
-   Keep customer dashboards, admin pages, case records, private
    documents and sensitive search parameters out of the index.
-   Use redirects deliberately and avoid redirect chains.
-   Return accurate HTTP status codes.
-   Add breadcrumbs and internal links.
-   Monitor Search Console/Bing Webmaster Tools and crawl errors after
    launch.

## 3. Structured data

Use schema.org structured data only when it accurately represents
visible page content. Candidate types include Organization, WebSite,
BreadcrumbList and Article. Use opportunity/product-like structured data
only after checking current search-engine guidelines and only when the
content genuinely qualifies. Do not fabricate ratings, reviews, price,
availability, awards or organization relationships.

Validate markup with appropriate testing tools. Structured data does not
guarantee rich results.

## 4. Content strategy

Prioritize genuinely useful content: - Opportunity detail pages with
evidence, eligibility, cost components and last-verified date. -
Category guides explaining business models and trade-offs. - Location
pages only where there is distinct, useful, verified local
information. - Guides on due diligence, contracts, working capital,
licenses, territory and application preparation. - Transparent pages
explaining verification, methodology, fees, conflicts of interest and
complaints. - FAQs based on real user questions.

Avoid mass-producing thin pages by combining every city, district and
category with near-identical text. Do not publish unsupported investment
claims or generic AI-written pages without expert review and source
checking.

## 5. Evidence and editorial rules

-   Label company-provided claims separately from independently
    confirmed facts.
-   Record source, reviewer and last-verified date for material claims
    internally.
-   Correct outdated information and unpublish opportunities that fail
    current verification rules.
-   Include uncertainty and exclusions, not only promotional benefits.
-   No fake reviews, success rates, testimonials, scarcity or earnings
    claims.
-   Ensure imagery and content have usage rights.

## 6. AI search and crawler policy

-   Review current crawler documentation and robots/CDN controls before
    launch.
-   Treat search/indexing crawlers and model-training crawlers as
    different categories; make an explicit policy decision for each
    relevant crawler.
-   Do not assume allowing a crawler guarantees inclusion or citation.
-   Publish accessible, substantive, factual content with clear
    authorship/ownership and dates where useful.
-   Do not expose private routes or documents to crawlers.

## 7. Performance and accessibility

-   Optimize images and use responsive sizes.
-   Minimize unnecessary JavaScript and render blocking resources.
-   Set cache policy carefully for public pages; never publicly cache
    private account/case responses.
-   Monitor Core Web Vitals using real deployment data.
-   Test mobile, keyboard use, contrast, focus and content semantics.

## 8. Measurement

-   Configure analytics only with appropriate privacy controls.
-   Monitor indexed pages, crawl errors, query impressions, qualified
    enquiries, page speed and content freshness.
-   Treat traffic and ranking as outcomes to measure, not guarantees.
